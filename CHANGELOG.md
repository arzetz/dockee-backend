# Changelog — dockee-backend

Фиксирует ключевые архитектурные решения и изменения между спринтами.  
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).

---

## [S1] - Инициализация проекта - 2025-02-03

### Added
- Инициализация репозитория dockee-backend (Go 1.24, go.mod)
- Базовая структура модульного монолита: `cmd/`, `internal/`, `migrations/`
- Docker Compose окружение: backend, postgres, minio, migrate
- Скелет HTTP-сервера на Gin с healthcheck `GET /health`
- Первичная OpenAPI-спецификация (openapi.yaml) — контракт согласован до реализации (API-First)
- Шаблон переменных окружения `.env.example`
- CI-пайплайн GitHub Actions: lint → test → build

### Decision
- Выбран модульный монолит вместо микросервисов  
  Reason: команда 5 человек, операционная сложность микросервисов избыточна на старте
- Выбран Go 1.24 как основной язык бэкенда  
  Reason: нативные горутины для асинхронного конвейера, статическая типизация, низкое потребление памяти

## [S2] - Аутентификация и управление учётными записями - 2025-02-17

### Added
- Регистрация пользователя с подтверждением email (`POST /api/v1/auth/register`)
- Аутентификация по логин/пароль (`POST /api/v1/auth/login`)
- Хранение паролей: bcrypt, cost factor 12
- Выдача JWT-токенов: access TTL 15 мин, refresh TTL 24 ч
- Ролевая модель RBAC: роли guest, user, admin
- Auth Middleware: верификация токена, помещение user_id в контекст запроса
- Audit Middleware: журнал событий безопасности с SHA-256 хешами идентификаторов
- Миграции: таблицы `users`, `user_profiles`, `user_balances`
- Юнит-тесты модуля auth: покрытие 74%

### Decision
- Выбрана токенная аутентификация (JWT) вместо сессионной  
  Reason: stateless — упрощает горизонтальное масштабирование, не требует разделяемого хранилища сессий

### Security
- Ключ подписи JWT передаётся через переменную окружения, не хранится в коде
- Audit-записи содержат SHA-256 хеши ID вместо реальных значений

## [S3] - Загрузка документов и файловое хранилище - 2025-03-03

### Added
- Загрузка документов PDF и DOCX до 20 МБ (`POST /api/v1/documents`)
- Интеграция с MinIO через S3-совместимый интерфейс
- Временные подписанные ссылки на файлы с TTL 5 минут
- Изоляция файлов по пользователю: ключ `{user_id}/{document_id}/{filename}`
- Список документов с сортировкой (`GET /api/v1/documents`)
- Удаление документа с очисткой файла из S3 (`DELETE /api/v1/documents/{id}`)
- Миграция: таблица `documents` со статусной машиной (queued → processing → done → error)
- Адаптер S3 Repository реализован за интерфейсом — провайдер заменяется переменной окружения

### Decision
- Файлы хранятся в объектном хранилище, не в СУБД  
  Reason: хранение BLOB в PostgreSQL увеличивает базу и замедляет резервное копирование

## [S4] - MVP: Anonymization Pipeline - 2025-03-10

### Added
- NER-anonymizer (ner.go): regex для российских форматов ПДн  
  Паттерны: ФИО, ИНН (10/12 цифр), серия/номер паспорта, СНИЛС, телефон (+7/8), email
- ai_connector.go interface: абстракция LLM-провайдера  
  Реализация: DeepSeek API, таймаут 90 с
- Асинхронный конвейер обработки в горутине (pipeline.go):  
  извлечение текста → NER-анонимизация → DeepSeek API → сохранение → обновление статуса
- Миграция: таблица `analysis_results` (JSONB для структурированного ответа ИИ)
- Юнит-тесты NER-модуля: таблица тест-кейсов с граничными значениями для каждого паттерна, покрытие 81%

### Changed
- Decision: переход с синхронной обработки на асинхронную (HTTP 202)  
  Reason: время ответа DeepSeek достигает 60 с — превышает таймаут API-шлюза при синхронном вызове

### Security
- Анонимизация встроена в pipeline.go как обязательный шлюз:  
  вызов ai_connector.go расположен после NER-этапа и не имеет альтернативного пути  
  raw document NEVER reaches DeepSeek API (Privacy by Design, ФЗ-152)

## [S5] - Результаты анализа и пользовательский интерфейс - 2025-03-24

### Added
- Эндпоинт результатов анализа (`GET /api/v1/documents/{id}/analysis`)  
  Возвращает: массив рисков с уровнями критичности, рекомендации, итоговый вывод
- Экспорт результатов в PDF (`GET /api/v1/documents/{id}/export`)
- История запусков анализа для каждого документа
- Управление профилем пользователя (`GET/PUT /api/v1/profile`)
- Тарифный баланс: проверка до запуска анализа, отклонение при нуле
- Polling-эндпоинт для отслеживания статуса обработки клиентом (интервал 3 с)

### Changed
- Схема ответа analysis_results расширена без изменения структуры таблицы (JSONB)

## [S6] - Полировка, тестирование и выпуск - 2025-04-07

### Added
- Интеграционные тесты: auth flow, document upload, anonymization pipeline
- Административные эндпоинты: список пользователей, блокировка, агрегированные метрики
- Эндпоинт журнала событий безопасности для администратора

### Changed
- golangci-lint конфигурация ужесточена: добавлены revive, gocyclo (порог 15), errcheck
- Обновлена OpenAPI-спецификация: все эндпоинты покрыты схемами запросов и ответов

### Fixed
- Утечка горутин при отмене контекста в pipeline.go (обнаружено go test -race)
- Некорректная обработка DOCX с вложенными таблицами в модуле извлечения текста

### Security
- gosec: устранены предупреждения G304 (file path traversal) в модуле извлечения текста
- Все SQL-запросы проверены на параметризацию (G201/G202)
